## 5. 性能疑点清单（阶段 A3，仅记录不动手，待 T4 实测验证）

| # | 疑点 | 机制 | 量级预判 | 证据 |
|---|---|---|---|---|
| P-1 | **【阻断 B3】归档桶条目全量常驻内存**：`t.archives` 里桶一旦加载（prune/冷读触发），entries map 永不驱逐 | B3 全量下冷数据持续累积在 RAM → OOM 风险；且冷读被美化成内存 map 命中，G1/G3 测量失真 | 20B ops 级必爆 | `mpt.go:173,457-473` 无驱逐路径 |
| P-2 | `rebuildFilter` 每次桶变更 O(桶大小) 全量重建 CF | prune 与每次赎回摘桶都触发 | 域桶随轮次增大后成本线性涨 | `mpt.go:554-569,747,580` |
| P-3 | `domainEntriesLocked` 每 prune 全扫一个域（默认每 batch 一次） | NodeIterator 遍历域内全部叶子 | 65536 域 × 每批 4000 ops 下，单域平均 ~数百叶子，可测 | `mpt.go:766-790` |
| P-4 | 逐 op 抢同一把互斥锁 + `ensureHotLocked` 检查；`PutBatch/DeleteBatch` 未合并成一次锁 | 4000 ops/batch = 4000 次 Lock/Unlock | 小但属于包装层拆账对象 | `mpt.go:608-609,663-664,678-685` |
| P-5 | `encodeArchive` 每次提交对脏桶全量 sort+序列化 | 赎回频繁的域每批都重编码整桶 | 与 P-2 同源 | `mpt.go:519-552,933` |
| P-6 | hash 后端 `writeNodeSet` 跳过删除标记、旧节点永不回收（T5 已知） | DB 体积膨胀（B3m3 12GB vs B0b 0.4GB 的旧账） | path 后端不受影响；hash 后端仅 A/B 用 | `mpt.go:806-819` |

## 6. 问题分级汇总

**阻断正式实验（阶段 B 必修）**

- epoch 位图 + 动态赋值（2.1）、Alg.1 四阶段（2.2-2.4）、stubList 挂树 + $C_{root}$ 覆盖（1.1）、ECMH 承诺与门控校验（1.1/3.2，C5 口径）、桶容量 n=100 与压实分裂（1.3）、桶 O(1) 更新（1.4）
