# AMT V14: domain-tail pruning and compact archive filters

V14 freezes replay source commit `3f62ca71d07b466dcd7ab0a29cd7d9847e86d26d`
as the combined successor to V13. It keeps V11 bucket aggregation, the RFC 9380
ECMH mapping, the existing two-root prune/operation pipeline, and all external
AMT interfaces. Relative to V13 it skips unrelated subtrees at the trailing
bits of the 19-bit prune domain, shares immutable stub lists across ordinary
hot-node path copies, batches additions to an existing bucket commitment,
computes domain IDs bytewise, and stores each cuckoo filter's slots in one
flat allocation. The filter's fingerprint algorithm and serialized bytes did
not change. The source branch is `codex/amt-v14-combined-opt-20261120`.

The uninstrumented MPT-server strict-block replay passed with exit code 0:
507 windows, blocks 46,147–10,000,000, and 20,242,112,513 state operations.
It pruned once per block, audited every redeemed bucket at commit, used 8
bucket workers and 2 workers per bucket, and sampled access classes every
1,000 operations. Its command matched V13 apart from binary and result paths;
`MPT_OP_TRACE` was off. Every window's block range and operation count matched
V13. Both ended with root
`0x28396767be12603f2c9660ad33173272422ec6a878253c8f11d5a90f65284055`,
22,965,042 hot leaves and 2,622,095 live buckets. Both recorded 3,680,431
full bucket verifications, 20,869,386 redemptions, 221,297,266 extracted
leaves, and 14,362,940,079 logical archive bytes. The V14 binary SHA-256 was
`766b1fe0a8615ee62edcc3817c0bcf3c075d44519d40367af51a0b6a957f8d10`.
The retained results are under
`AMT实验结果/v14_final_candidate_full_20261120/full/` in the paper workspace.
The historical directory name remains unchanged after naming this run V14.

Block-time throughput uses `Parse + Operations + Commit + DB_Write -
Proof_Verify` for AMT and `Parse + Operations + Root + DB_Write` for native
MPT. Pruning and bucket verification are excluded from that denominator and
shown separately.

| --- | ---: | ---: | ---: |
| Block-time throughput, operations/s | 308,188 | 281,275 (91.27% of MPT) | 280,397 (90.98% of MPT) |
| Archive maintenance, seconds | n.a. | 19,036.367 | 11,751.697 |

V14 cuts archive maintenance by 38.27% versus V13: extraction 2,343.185 to
757.106 seconds, mounting 12,760.601 to 6,861.239 seconds. The intermediate
root rose from 3,878.493 to 4,080.378 seconds. The 19-bit domain skip reduced
resolved prune nodes from 1,408,430,009 to 357,843,024. The final logical
archive bytes and bucket occupancy (P50 99, P95 100) match V13. Final system
bytes rose slightly, from 13.010 to 13.031 GB, despite much lower heap use.

All-cost throughput improved 8.27% versus V13. Full-run block-time throughput
was 0.31% lower, within the variation of these single runs; it must not be
described as an improvement. For the last ten windows, block-time throughput
rose from 269,886 to 271,383 operations/s (93.28% to 93.80% of MPT), and
all-cost throughput rose from 216,726 to 229,953 operations/s. These are
observations from one run per version, not a confidence interval or a causal
estimate for any individual code change.

The one-final-root switch was screened on the same first 100 windows and
produced the same root. It reduced total time only 0.33% while raising the
block-time denominator 1.65%, because work moved from archive maintenance
into the final commit. V14 therefore retains the established two-root timing
scope. The first 100 windows of the flat-filter candidate also passed a
same-server A/B with identical root, operation counts, hot leaves, buckets,
and staged hot-node bytes. The filter's fixed pre-change wire fixture decoded
and re-encoded identically; local `BenchmarkFilterNew` dropped from about
526 ns, 1,200 B and 34 allocations to 68 ns, 304 B and 2 allocations, while
lookup latency stayed about 355 ns.

The hot-tree performance gap remains: V14's state operations took 51,745.881
seconds versus native MPT's 43,662.366 seconds. Local resident and in-memory
unresolved-node microbenchmarks did not show a similarly large `hx` lookup
penalty. AMT `Get` adds a returned-value copy (about 60 ns and 32 B in a
32-byte resident-value microbenchmark), but changing its ownership contract
was excluded from V14. Archive metadata memory, cache behavior, and real-trace
node resolution still need symmetric profiling before a further hot-path
rewrite. Do not attribute the entire operations gap to trie recursion.
