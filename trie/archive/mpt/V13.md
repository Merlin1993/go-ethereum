# AMT V13: parallel commitments and coalesced stub refresh

V13 freezes source commit `2622d697a1a2d35eb1c9b384261a56867c395cca`
as the first combined successor to V12. It retains V11 bucket aggregation and
the RFC 9380 ECMH mapping. Relative to V12, it includes hot-trie path copies,
parallel ECMH creation for new buckets, a shared hash-to-curve worker pool for
full bucket audits, and coalesced stub refreshes. The short A/B candidate that
changes stub-list representation (`717374572`) is **not** in V13 because its
real-trace timing benefit was not stable.

The uninstrumented MPT-server strict-block replay used the same 507 windows,
blocks 46,147–10,000,000, and 20,242,112,513 state operations as the V12 and
B1 native-MPT runs. It pruned once per block, audited every redeemed bucket at
commit, used 8 bucket workers and 2 workers inside each bucket, and sampled
access classes every 1,000 operations. The test passed with exit code 0 and
final root
`0x28396767be12603f2c9660ad33173272422ec6a878253c8f11d5a90f65284055`,
identical to V12. The result directory is
`AMT实验结果/v12_combined_full_20261118/full/` in the paper workspace; its
historical directory name is retained to avoid rewriting experiment records.
The replay binary SHA-256 was
`153f443ee9242df693624473d4e4d359a920677c161968cd1cadf43dcd70377c`.

For block-time throughput, AMT uses `Parse + Operations + Commit + DB_Write
- Proof_Verify`; B1 MPT uses `Parse + Operations + Root + DB_Write`. Pruning
and bucket verification are excluded from the block-time denominator:

| Metric, full replay | B1 native MPT | V12 | V13 |
| --- | ---: | ---: | ---: |
| Block-time throughput, operations/s | 308,188 | 280,146 (90.90% of MPT) | 281,275 (91.27% of MPT) |
| Archive maintenance, seconds | n.a. | 20,953.288 | 19,036.367 |
| Full bucket verification, seconds | n.a. | 5,436.021 | 2,122.949 |
| Throughput including maintenance and verification, operations/s | 308,188 | 205,202 (66.58% of MPT) | 217,365 (70.53% of MPT) |

V13 improves block-time throughput by 0.40% versus V12 in this full run,
archive maintenance by 9.15%, and bucket verification by 60.95%. The final
ten windows reached 93.28% of MPT in the block-time scope. The modest
full-run block-time difference has not been repeated and should not be
attributed to any single change. The all-cost comparison includes work MPT
does not perform and is reported separately.

Pruning remains the largest cost outside block time. Of V13's 19,036.367
seconds, bucket mounting took 12,760.601 seconds, intermediate-root commit
3,878.493 seconds, and hot-tree extraction 2,343.185 seconds. The epoch
aggregate already implements CanSkip; a possible next improvement is to use
the trailing bits of the 19-bit domain before leaf-level filtering. Bucket
append and stub mounting need more precise counters before changing their
algorithms. A single-final-root path exists behind the replay flag and has
a small correctness oracle, but its real-trace total-time effect is untested.

Future changes must start from this frozen version in a separate branch or
worktree. Compare a combined candidate with V13 using identical windows and
timing scope, validate the final root and bucket audits, and keep pruning,
verification, storage, and block time separate. A new version requires a
successful full replay; short benchmarks are only screening evidence.
