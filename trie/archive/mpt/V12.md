# AMT V12: epoch aggregate fast path

V12 builds on the V11 bucket aggregation and operation trace commit
`c23fbbb89e50a954af2415925a70752a2928327a`. Its only behavior change is
in `hx.subtreeAggOf`: the aggregate of a full node's sixteen packed two-bit
child states is computed from the two bit planes instead of scanning every
slot. The representation, archive buckets, ECMH commitment, pruning rules,
and serialized trie nodes are unchanged.

The equivalence test covers boundary values and 100,000 deterministic packed
states. `go test ./trie/archive/mpt/hx ./trie/archive/mpt -count=1` passes.

On the MPT server, the uninstrumented V11/V12 comparison over the same first
50 block windows (29,689,693 operations) changed AMT/MPT throughput from
89.92% to 91.16%. The full uninstrumented V12 replay passed: 507 windows,
20,242,112,513 operations, and final root
`0x28396767be12603f2c9660ad33173272422ec6a878253c8f11d5a90f65284055`,
matching the earlier V11 timing replay. With pruning and verification outside
the block-time denominator, full V12 throughput was 90.90% of the same-server
B1 MPT replay. The full uninstrumented V11 replay was not repeated, so the
full-run gain attributable solely to this change is not measured.

Before naming a later performance version, compare it with V12 on the same
server, trace, block windows, and timing scope with diagnostic probes off.
Require identical operation counts and state roots, passing bucket audits,
and a repeatable improvement in the primary block-time throughput metric.
Check pruning, verification, storage, and bucket distribution for regressions
before promoting the candidate. Keep experiments in separate branches and
result directories; a candidate that does not pass these checks is not a new
version.
